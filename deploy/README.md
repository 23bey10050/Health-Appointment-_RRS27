# Deploying to Render + Neon

Two services on Render's free tier (API + static frontend), Postgres on Neon,
Redis on Render Key Value, scheduled jobs on GitHub Actions.

Everything below has been verified against the current code except the Render and
Neon provisioning itself, which needs your accounts.

---

## Before you start: what free tier costs you

| Limit | Effect | Mitigation in place |
|---|---|---|
| No Background Workers or Cron on Render free | Celery worker + beat can't run | `/api/v1/jobs/*` endpoints driven by GitHub Actions cron |
| Service sleeps after 15 min idle, ~50s cold start | First voice session after a quiet period is very slow | The 10-minute cron tick keeps it warm |
| 512MB RAM | `fastembed` loads ~130MB of models, reranker adds ~90MB more | If it OOMs, see "If the service runs out of memory" below |
| No persistent disk | Embedding models re-download on cold start | Keep-alive avoids most cold starts |

If any of this matters for real use, one paid Render Background Worker (~$7/mo)
removes the first two rows entirely and lets you run Celery as designed — the
task wrappers were left intact for exactly that.

## 1. Neon (Postgres)

1. Create a project. Note the **direct** connection string — the one *without*
   `-pooler` in the hostname.
2. Convert it for asyncpg:
   ```
   postgresql+asyncpg://USER:PASSWORD@ep-xxxx.eu-central-1.aws.neon.tech/neondb?ssl=require
   ```
   Two things people get wrong here, both of which fail silently or confusingly:
   - It must be `?ssl=require`, **not** `?sslmode=require`. `sslmode` is a
     libpq/psycopg parameter; asyncpg rejects it.
   - It must be the direct endpoint. `services/booking.py` uses
     `pg_advisory_xact_lock`, which does not survive PgBouncer in transaction
     mode — the pooled endpoint would break double-booking protection without
     any error message.

3. Run the migrations once, from your machine:
   ```bash
   cd backend
   ALEMBIC_DATABASE_URL='postgresql+asyncpg://...?ssl=require' alembic upgrade head
   ```
4. Confirm the extensions and the constraint actually landed:
   ```sql
   SELECT extname FROM pg_extension;   -- expect uuid-ossp, vector, btree_gist, citext
   \d appointments                     -- expect constraint "appointments_no_overlap"
   ```
   If `appointments_no_overlap` is missing, `btree_gist` didn't install and
   double-booking protection is **not active**. Stop and fix that before going
   further — it is the one constraint the whole booking design rests on.

5. Seed reference data:
   ```bash
   DATABASE_URL='postgresql+asyncpg://...?ssl=require' python -m scripts.seed
   DATABASE_URL='postgresql+asyncpg://...?ssl=require' python -m scripts.seed_kb
   ```

## 2. Redis (Render Key Value)

Create a free Key Value instance and copy its connection URL.

**Set the eviction policy to `noeviction`.** This is not a performance tuning
choice. Redis holds the refresh-token blacklist and single-use voice tickets, so
under `allkeys-lru` an eviction silently un-revokes a logged-out token or lets a
voice ticket be replayed. Those are security regressions, not cache misses.

## 3. Render services

Push the repo, then **New → Blueprint** and point it at `render.yaml`. It defines
both services. Set the secret env vars in the dashboard:

**API service** — `DATABASE_URL`, `REDIS_URL`, `CALENDAR_TOKEN_ENCRYPTION_KEY`,
`GROQ_API_KEY`, `GEMINI_API_KEY`, `BREVO_API_KEY`, `GOOGLE_CLIENT_ID`,
`GOOGLE_CLIENT_SECRET`, `EMAIL_FROM`, `ONCALL_ALERT_EMAILS`.
`JWT_SECRET` and `JOBS_SECRET` are auto-generated by the blueprint — copy
`JOBS_SECRET`, you need it in step 4.

**Ordering problem, worth knowing:** `APP_BASE_URL` on the API must be the
*frontend's* URL, and `VITE_API_BASE_URL` on the frontend must be the *API's*
URL. Neither URL exists until its service is created, so deploy both, then set
both, then redeploy both. `APP_BASE_URL` is load-bearing — it is simultaneously
the CORS origin, the OAuth redirect base, the email link base, and the ICS UID
domain.

`VITE_API_BASE_URL` is inlined by Vite at **build** time, so changing it requires
a rebuild, not just a restart.

### Google OAuth

Register the exact redirect URI in Google Cloud Console:
`https://YOUR-API.onrender.com/api/v1/calendar/callback`, and set
`GOOGLE_REDIRECT_URI` to the same string. Google matches it verbatim.

## 4. Scheduled jobs (GitHub Actions)

`.github/workflows/scheduled-jobs.yml` is already in the repo. Add two repository
secrets under Settings → Secrets and variables → Actions:

- `API_BASE_URL` — `https://YOUR-API.onrender.com`
- `JOBS_SECRET` — the value from the API service

Trigger it once manually (Actions → Scheduled jobs → Run workflow) and confirm a
200. Then check `email_outbox` has no rows stuck in `pending`.

If `JOBS_SECRET` is unset on the API, these endpoints return **503, not 200** —
they fail closed rather than running unauthenticated.

## 5. Verify the deployment

In order; each depends on the last.

1. `curl https://YOUR-API.onrender.com/health` → `{"status":"ok"}`
2. Load the frontend, log in as a seeded user. If login fails with a CORS error,
   `APP_BASE_URL` doesn't exactly match the frontend origin (scheme, no trailing
   slash).
3. Book an appointment through the UI — exercises Postgres, the advisory lock and
   the exclusion constraint.
4. **In Chrome**, start the voice assistant and speak. Confirm the transcript
   appears and the reply is spoken back.
5. Say something critical ("crushing chest pain radiating to my arm"). The red
   banner must appear, and `emergency_queue` must gain a row.
6. **In Firefox**, confirm the page shows the "speech input isn't available"
   notice and typing still works.
7. Trigger the jobs workflow manually; confirm 200 and that email dispatch moves
   outbox rows.
8. Hit `/api/v1/auth/login` 11 times quickly — the 11th must return 429. If it
   doesn't, `--proxy-headers` isn't being applied and every user is sharing one
   rate-limit bucket.

## Browser support

STT is the Web Speech API: **Chrome and Edge only**. Firefox has no
implementation; Safari's is unreliable. The UI detects this and tells the user to
type instead — typed input goes through the identical agent, safety and booking
path, so nothing is lost except voice.

Speech audio is transcribed by the browser vendor's service (Google, for Chrome).
The consent screen states this. If you later need audio to stay on your own
infrastructure, the server-side Whisper path was removed in this migration and
would need restoring.

## If the service runs out of memory

512MB is tight with `fastembed`. In rough order of preference:

1. Disable reranking — set `RERANK_SCORE_GAP_THRESHOLD=0` so the reranker never
   loads (~90MB saved). Retrieval still works via Reciprocal Rank Fusion; results
   are slightly less well ordered.
2. Drop the `[rag]` extra entirely. The voice agent falls back to no retrieved
   context — it still books appointments and the safety layer is unaffected,
   since red-flag matching is deterministic and never used RAG.
3. Upgrade to a paid instance.

## Local development is unchanged

`docker compose up` still runs everything locally, including Postgres for the
test suite. Do **not** point the tests at Neon: `tests/conftest.py` does
`DROP DATABASE`/`CREATE DATABASE` against the maintenance database, and
`test_booking_concurrency.py` opens 50 simultaneous connections — neither works
on a managed free tier.
